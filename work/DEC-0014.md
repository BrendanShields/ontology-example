The candidate spec asked for a local ontology MCP server with five tools. A stdio prototype with three read-only tools was built in a scratch directory and driven with the MCP SDK's own client. The numbers below were measured during that validation and were not run again for this record.

| The spec's tool | What answers it today |
| --- | --- |
| `ontology_describe` | `onto overview`, `onto resolve <name>`, `onto slice --task <id>` |
| `get_active_decisions(component)` | `onto cq CQ-03 --bind term=<term>` by term, `onto cq CQ-10 --bind path=<file>` by path, and every slice |
| `sparql_query` | `onto cq`: vetted questions only, each with a test that pins its answer |
| `dry_run_action` | `onto new --dry-run` and `onto ocr new --dry-run` |
| `propose_decision` to a staging area | `onto new Decision status=draft`: a draft is not in force |

Measured:

- The prototype's output matched the command line byte for byte for `overview` (1,939 bytes) and `slice` (6,637 bytes). `cq` differed by one trailing blank line.
- Speed favours the server and is not the reason: a warm call took 25 to 44 ms against 210 to 250 ms for one command, after about 0.6 s to start. Importing the `mcp` package alone took 0.46 s, and it is not a dependency of this repository.
- Free-form SPARQL on "decisions about score" returned DEC-0003, DEC-0004, DEC-0005 and DEC-0006. CQ-03 returned DEC-0005 and DEC-0006, which is right: the other two are superseded.
- A `SERVICE` clause in a free-form query made a real HTTP request to a listener on the same machine. A four-way join had not finished after 5 seconds, and the store has no time limit.
- A server that holds a workspace open goes stale: it did not see a new work item and still resolved an alias that had been removed.

What a server cannot do: put a slice into a subagent's context when it starts, block an edit, or hold a stop. Hooks do those, and they run the command line.

Adopted from the investigation, in the command line: `--dry-run` on `onto new` and `onto ocr new`, a refusal of `SERVICE` in a query, and a clear error for `CONSTRUCT` and `DESCRIBE`.

This Decision would change for an adopting team whose client speaks MCP and has no shell. The right shape then is an optional adapter that is off by default: read-only tools over the same functions the commands call, a fresh workspace on each call, no free-form query tool and no write tool, with a test per tool that its text equals the command's output. That adapter was not built. That a shell-less client needs it is an inference, not something observed.
