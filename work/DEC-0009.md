"Its logs" in REQ-0008 means everything the app writes other than its result on stdout:

- what `call-qa` writes to stderr, the `--trace` output included
- every record that reaches a Python logger while a command runs, the loggers of the Anthropic SDK and its HTTP client included
- every file the app writes. The first one is the ledger of DEC-0011, and the same rule holds for it.

What follows from it in the code:

- `--trace` shows, for each tool call, the tool, the Criterion, the outcome, the Utterance numbers cited and the rule names of any Rejection. It does not show the tool input or the tool result.
- A Call, Scorecard or replay file that cannot be read is reported by file, position, field and kind of error. The value that was wrong is not echoed, and neither is a line of the file.
- An error from the API is reported by its status and type. Its message is not, because the API can quote the request.
- The SDK's loggers are held at WARNING while a command runs, whatever `ANTHROPIC_LOG` says. At DEBUG the SDK logs each request whole, which is the whole Call.
- An error nobody expected is reported by its class and the place it was raised, without its message.

What it does not cover, and an operator still has to decide:

- stdout. The Evaluation is the result and it holds every rationale. `call-qa prompt` and `call-qa tools` print no part of a Call.
- the request to the model, which carries every Utterance. That is the work itself, not a log.
- a handler or a debugger an operator attaches to the process, and a shell that records what the command printed.
