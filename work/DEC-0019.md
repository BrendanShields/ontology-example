The goal is a framework another team can pick up. Four routes were weighed.

| Route | Verdict | Reason |
| --- | --- | --- |
| `onto init`, from templates inside the package | chosen | one command in an existing repository. Every path is then read from `onto.toml` |
| a Claude Code plugin that carries the skills, agents and hooks | not now | the hooks must run `onto` from the adopter's own environment, and the gates must also run in CI, where no plugin is loaded |
| a mandated directory tree, as the candidate spec lays out | rejected | the layout is configuration here. A scratch adopter with `src/loans/` and no `apps/` ran every command |
| an MCP server as the way to consume the ontology | rejected | see DEC-0014 |

Evidence from validation, measured then:

- The package built and installed outside this workspace: the console script, the pytest plugin and the `gen` extra all worked from a wheel.
- The wheel held 26 Python modules and no data. With only the wheel, `validate`, `trace`, `view` and `new` exited 2.
- A scaffold made by hand, of ten files and a three-class glossary, ran `new`, `validate`, `check-terms`, `guard`, `evidence collect`, `trace`, the Stop hook payload, `slice` and `resolve` with no change to the code.
- The worst coupling found was the namespace. It was written as text in the gates and in every competency question. Changing it in the workflow ontology alone made `onto trace` pass with the gates silently matching nothing. `onto init` now writes one namespace everywhere, and `onto trace` reports `error[namespace]` when a gate or a question disagrees with the workflow ontology.

What ships:

- `onto init [--context NAME] [--domain-path GLOB] [--base-uri URI] [--onto-cmd COMMAND] [--no-claude] [--no-ci]`. It writes missing files and never overwrites one.
- Templates under `packages/onto/src/onto/templates/`. `synced/` is a copy of this repository's `ontology/` and `.claude/`, regenerated by `make templates`, and a test fails when it is stale. `static/` is written by hand.
- `docs/adopting.md`, and `packages/onto/tests/test_adoption.py`, which scaffolds a repository and walks the guide's steps.

Limits a reader must know:

- There is no upgrade path. `onto init` writes only what is missing, so an adopter who wants a newer gate or skill carries it across by hand.
- Evidence is recorded by a pytest plugin, and the generated types are Python.
- `onto init` scaffolds one bounded context. A second is added by hand, with its deny rules.
- The scaffolded Claude Code layer has not been opened in Claude Code.

This Decision would change when adopters ask for upgrades, which calls for an `onto upgrade` and versioned templates, or when a plugin can serve hooks and CI from one source.
