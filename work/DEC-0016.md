The candidate spec asked for a PostToolUse hook that, on every edit, regenerates, lints, checks imports, runs the graph gates and runs the whole test suite, exiting 2 on any failure. It also asked for a gate that blocks on code comments. Both were measured during validation and rejected.

The whole suite after every edit:

- Measured then, median of three: `onto gen` 0.63 s, `ruff check` 0.03 s, import-linter 0.08 s, `onto trace` 0.54 s and the test suite of that day 8.54 s. About 9.8 s for each edit, against 0.04 to 0.21 s for the guard and 0.21 s for the term check. `make check` now takes a little over three minutes, so the same hook today would cost far more.
- The Claude Code hooks reference says a PostToolUse hook cannot block: the tool has already run, and the hook can only send text back.
- The edits in the middle of a change that spans several files are expected to fail tests. The agent would be told about failures it is in the middle of fixing.

What runs when, as wired in `.claude/settings.json`:

| When | What | Measured by `make hooks` on 2026-11-26, one Apple laptop |
| --- | --- | --- |
| before an edit | `onto guard` | 0.05 to 0.21 s |
| after an edit | `onto check-terms` on the file | 0.05 to 0.26 s |
| when Claude stops | `onto trace --gate stop --scope branch --collect`: the gates for what the branch touched, and the tests its Test items name | 0.40 to 1.02 s on the scratch repository the driver uses |
| `make check` and CI | everything, with the whole suite and the mutants | 194 s here |

`tools/drive_hooks.py` fails when a hook that runs on an edit takes longer than its budget, 0.5 s by default. That is the check that holds this Decision.

A gate that blocks on comments:

- A census during validation found 120 comments in 4,528 lines of the tooling and 28 in 1,149 lines of the app. The gate would have failed on its first run.
- The escape from the term check, `# onto: allow-term`, is itself a comment, and so is ruff's `noqa`.
- Nothing exact tells a comment that gives a reason from one that narrates. The rule in this repository is that blocking is kept for what is exact.

Comment hygiene stays a matter for review. What was adopted instead: the import contracts in `make check` and CI, the guard on the files that configure the gates, deny rules for generated files and evidence, and the branch gates that find an ontology change after the fact whatever tool made it.

This Decision would change if Claude Code let a hook after an edit undo the edit, or if a check as wide as the suite ran in well under a second.
