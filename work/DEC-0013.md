The candidate spec asked for the LinkML sources to be compiled to OWL and for `owl:FunctionalProperty` and `owl:disjointWith` to enforce invariants. This was tested before anything was built. The numbers below were measured during that validation, on scratch copies, and were not run again for this record.

| The spec's axiom | What it did under OWL 2 RL (owlrl) | What rejects instead |
| --- | --- | --- |
| `owl:FunctionalProperty` with two values | inferred that the two values are the same thing, with no error | `sh:maxCount`, generated from the LinkML slot |
| `owl:disjointWith` | wrote an error triple into the data graph, which pyshacl does not report: conforms | `sh:not` with `sh:class` |
| `owl:oneOf` | inferred that the outside value belongs to the class | the LinkML enum: a Pydantic Enum, the strict tool schema, `sh:in` |
| `rdfs:domain` and `rdfs:range` | retyped the wrong nodes, which hides the error | `sh:class`, with inference off |

Evidence:

- Seven small cases, each run with pyshacl at `inference=None`, at `inference='owlrl'` and through the owlrl closure alone. With OWL axioms and no shapes, all seven conformed in both pyshacl modes. Each SHACL equivalent reported its violation with inference off.
- Turning inference on removes a violation this repository depends on. The graph leaves an unknown term untyped so that `sh:class wf:Term` fires. With `rdfs` or `owlrl` inference and a range axiom, the same graph conforms. That is why `gates.py` passes `inference=None`, and why it must stay that way.
- `gen-owl` on the call-qa glossary ran cleanly and produced 762 lines with no `FunctionalProperty`, no `disjointWith` and no `oneOf`. Enums become a union of classes. The three axioms the spec names are not what LinkML emits for this glossary.
- One Finding per Criterion is uniqueness across sibling objects. No cardinality on one property expresses it: not a functional property, not `sh:maxCount`, not the generated type. A hand-written `sh:sparql` shape or guardrail code can. The app holds it in the guarded write path and in `scoring.conclude` (REQ-0010).
- A SHACL check of each proposal at runtime was also considered and rejected. It measured 4 to 9 ms, so speed is not the reason. It needs a third hand-written mapping from the types to RDF, and the first attempt at that mapping gave 15 false violations on a valid Evaluation.

Which mechanism carries which invariant:

- A closed set: a LinkML enum.
- At most one, or required, on one slot: the LinkML slot, compiled to the type and to `sh:maxCount` and `sh:minCount`.
- A link between work items: `sh:class`, inference off.
- A rule across work items: a hand-written `sh:sparql` shape in `ontology/shapes/gates.shacl.ttl`.
- A rule across the objects of one Evaluation: domain code that answers with a Rejection.

One thing was adopted from this investigation. `packages/onto/tests/test_generator_agreement.py` holds the generated types and SHACL generated in memory from the same schema to the same answer on synthetic instances.

No OWL file is generated or committed in this repository. If another system needs one, run `gen-owl` on the same sources and treat the output as an export. This Decision would change if a gate needed an inference that SHACL cannot state, and then the gate would still be a shape over the inferred graph and not the axiom itself.
