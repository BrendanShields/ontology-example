id: OCR-0004
proposed_term: Incident
proposed_definition: >-
  Incident: something observed in operation that the system should not have done. A Requirement
  can be raised_from an Incident and can replace an earlier Requirement. A Decision can name
  the repository paths it affects.
justification: >-
  The workflow ontology stops at ship, so a defect found in operation and a changed business
  rule have no typed route back into Requirements. Two graph gates go with it: a superseded
  Requirement names its successor, and a closed Incident has a verified fix. This edits ontology/workflow.yaml
  and ontology/shapes/gates.shacl.ttl, which every bounded context shares.
title: >-
  Extend the workflow ontology past ship: Incident, raised_from, replaces, affects
status: draft
bounded_context: call-qa
