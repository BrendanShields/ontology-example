The candidate spec asked for a verification bundle under `artifacts/verify/`: a property-test summary, a SHACL report, dry-run traces and a Mermaid statechart.

| Part of the spec's bundle | Verdict | What there is |
| --- | --- | --- |
| a property-test summary | already here | `work/evidence/EVD-*.md`, one per Test, written by the test run |
| a SHACL report | already here | `onto trace --format json` |
| dry-run traces | adapted | replays run offline. The index records ids, outcomes and rule names only, because a trace of a replay holds Finding rationales |
| a Mermaid statechart | adapted | two diagrams generated from runs of the real code, under `apps/call-qa-agent/docs/`, each held to the code by a test (DEC-0015) |
| one place to open | adopted | `prov/verify.json`, written by `onto verify` |
| the path `artifacts/verify/`, committed | rejected | `prov/` was already the derived, git-ignored place that CI uploads |

`onto verify` runs `gen --check`, `validate`, `check-terms`, `evidence collect`, `trace`, `rules` and `prov emit`, goes on after a failure, and exits 1 if any of them failed. The index is written either way.

Rules the index keeps:

- It records ids, counts, statuses, rule names, paths and hashes. It never stores the output of a gate, the message of a violation, the title of a work item or the text of an exception. So it cannot carry the text of an Utterance or a rationale.
- Everything that differs between two runs on the same tree sits under one key, `varies_per_run`.
- It is derived and not committed. A committed index would be a claim that nobody reran.

`onto verify` is not `make check`. It runs only the pytest nodes that Test items name. It does not run the linter, the import contracts, the whole suite or the vendoring check.

Limits: the competency questions under `ontology/cq/` are not among the sources it hashes. The provenance bundles written beside the index carry work item titles and decision-log text by design, so the rule about text covers `verify.json` and not the `.ttl` files.

This Decision would change if a reviewer or an auditor needs the index at a commit without running anything. Then CI's uploaded artifact is the first answer, and a signed attestation the second, before committing the file.
