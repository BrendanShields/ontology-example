Once a monorepo has 30 packages and 12 namespaces, you can't load everything into context. The agent ends up with too much to read and no way to know which part matters.

[next]

A fast decision-model router picks what to load. LangChain and TypeSafe don't talk about ontologies, so this is where the two patterns combine in our stack: we compile the router's valid choices straight from the ontology, so it can only pick a namespace that exists, in milliseconds. For a billing task it loads packages/billing/CLAUDE.md, the /change-business-rule skill and the billing namespace — 1 of the 12. Nothing else enters context.

Here is a trap from the OpenMetadata and Collate docs. An agent that invents a predicate gets zero rows and no error. It reads that as nothing there, and it carries on with a wrong answer. A SQL query against a missing column would at least fail.

[next]

Their answer is five MCP tools in place of free-form access: ontology_describe, entity_neighborhood, find_by_tag, sparql_query and shacl_validate. The agent calls describe first, so it knows which predicates exist before writing a query.

One note for accuracy. In Collate's design, shacl_validate is read-only and never blocks the write path — it audits metadata gaps. The blocking use of the same shapes is our Gate 2 from the previous slide. We also print the exact SPARQL query in the PR evidence so a reviewer can rerun it and see the same rows.
