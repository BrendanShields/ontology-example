Once a monorepo has 30 packages and 12 namespaces, you can't load everything into context. The agent ends up with too much to read and no way to know which part matters.

[next]

A System 1 router picks what to load. We compile the router's valid choices from the ontology, so it can only pick a namespace that exists, and it picks in milliseconds. For a billing task it loads packages/billing/CLAUDE.md, the /change-business-rule skill and the billing namespace, which is 1 of the 12. Nothing else goes into context.

Here is a trap from the OpenMetadata and Collate docs. An agent that invents a predicate gets zero rows and no error. It reads that as nothing there, and it carries on with a wrong answer. A SQL query against a missing column would at least fail.

[next]

Their answer is five tools in place of free-form access. The tools are ontology_describe, entity_neighborhood, find_by_tag, sparql_query and shacl_validate. The agent calls describe first, so it knows which predicates exist before it writes a query.

One note for accuracy. In their docs, validation never blocks the write path, and shacl_validate is read-only. The blocking use of the same shapes is our Gate 2 from the previous slide. We also print the exact query in the PR evidence, so a reviewer can rerun it and see the same rows.

The last point is about enforcement. CLAUDE.md is advisory, and a PreToolUse hook is enforced. An agent can skip a line in CLAUDE.md, and it can't skip a hook. Locks on generated files belong in hooks.

That covers the agent. The last piece is the people who review its work.
