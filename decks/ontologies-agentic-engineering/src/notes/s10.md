Most schemas stop at nouns, and this slide argues they shouldn't. The first box is data. It holds the nouns, Customer and RefundRequest. A passive schema covers this box and nothing else.

[next]

The second box is logic, the rules. evaluate_refund() is deterministic Python. The language model never does the arithmetic. It can choose which function to call, and the function computes the limit.

[next]

The third box is actions. These are verbs, not CRUD. issue_refund is an action with preconditions, and it carries a tag that says REVERSIBLE or IRREVERSIBLE. That tag is my own convention for this talk. It is not a Palantir term.

[next]

Binding data, logic and actions together comes from Palantir's Ontology, and they deserve the credit for it. Their Ontology SDK, OSDK, compiles that business model into typed TypeScript, Python and Java clients.

On the slide, all three boxes feed into one compiled typed SDK, which gives our own code three properties.

APIs, background workers and AI agents all call the same typed functions — an agent can't take a shortcut a normal service couldn't.

Each action declares whether it can be undone, so you know where human approval belongs before anyone argues about it.

And because every write goes through a named action, the list of actions taken is already the audit log.

If this sounds like the expert systems of the 1980s, that is a fair objection — let's take it quickly before we wire this around a coding agent.
