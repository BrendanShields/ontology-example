This is one change, end to end, in an illustrative billing monorepo. The request is to allow ENTERPRISE auto-refunds up to $1,000 while keeping PRO at $500. There are six stops, so I'll keep each one short.

The first stop is ground. The agent calls ontology_describe and get_active_decisions. That loads ADR_004 and hides ADR_001, because ADR_004 superseded it.

[next]

The second stop is the spec. The agent tries to edit billing.py directly, and a PreToolUse hook denies the edit because billing.py is generated. The agent edits billing.yaml instead, which compiles the SDK, the schema shapes and the docs.

[next]

The third stop is code. The agent updates refunds.py and slips in an inline comment. The no-comments check fails with exit code 2, and the agent removes the comment.

[next]

The fourth stop is verify. Ruff and import-linter run first. Hypothesis then fuzzes 1,000 pairs of PlanTier and amount, including the boundary of $1,000.00 against $1,000.01. Gate 2 blocks a double refund in the same run.

[next]

The fifth stop stages the ADR. When the agent tries to finish, a Stop hook blocks the exit until propose_decision stages a valid ADR_005 that supersedes ADR_004. The new record waits for review. Nothing merges it into decisions.ttl yet.

[next]

The last stop is review. A person opens one file, artifacts/verify/PR_EVIDENCE.md. It holds a statechart, the Hypothesis result, the SPARQL query and the staged ADR diff.

The reviewer reads that evidence file and not 400 lines of diff. They can rerun the query, check that the boundary cases are the right ones, and approve the decision record on its own terms.

That is the system working. Now the ways it goes wrong.
