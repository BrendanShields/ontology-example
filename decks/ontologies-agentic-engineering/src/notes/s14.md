This is one change, end to end, in an illustrative billing monorepo. The request is to allow ENTERPRISE auto-refunds up to $1,000 while keeping PRO at $500. There are six stops, so I'll keep each one short.

The first stop is ground. The decision-model router picks the billing namespace, and the agent calls ontology_describe and get_active_decisions. That loads ADR_004 and hides ADR_001, because ADR_004 superseded it.

[next]

The second stop is the spec. Remember the enforcement rule: CLAUDE.md is advisory and an agent can skip a line in it, while a PreToolUse hook is enforced. Here the agent tries to edit generated billing.py directly, and the hook denies the edit. It edits the LinkML billing.yaml instead, which compiles the SDK, the schema shapes and the docs.

[next]

The third stop is code. The agent updates refunds.py and slips in an inline comment. Following Lauren Tan's gardening rule, the no-comments check fails with exit code 2, and the agent removes the comment.

[next]

The fourth stop is verify. Ruff and import-linter run first. Hypothesis then fuzzes 1,000 pairs of PlanTier and amount, including the boundary of $1,000.00 against $1,000.01, while Gate 2 validates the dry-run against the OWL and SHACL rules.

[next]

The fifth stop stages the ADR. When the agent tries to finish, a Stop hook blocks the exit until propose_decision stages a valid ADR_005 that supersedes ADR_004. The new record waits for review. Nothing merges it into decisions.ttl yet.

[next]

The last stop is review. A person opens one file, artifacts/verify/PR_EVIDENCE.md. It holds a statechart, the Hypothesis result, the SPARQL query and the staged ADR diff.

The reviewer reads that evidence file and not 400 lines of diff. They can rerun the query, check that the boundary cases are the right ones, and approve the decision record on its own terms.
