Here are the names I have avoided so far, the four standards Netflix used. I'll take them one at a time.

RDF stores facts as triples. Each fact has a subject, a predicate and an object. ADR_005 supersedes ADR_004 is one triple.

[next]

SPARQL is the query language over those triples. It runs exact multi-hop queries. Ask what replaced ADR_001 and the query walks the supersedes links back to ADR_005.

[next]

The next two are where I see the most common mistake, which is treating them as the same thing. OWL works in an open world. If a fact is unstated, OWL treats it as unknown, not false. OWL is for inference, using property chains like grandfatherOf and contradictions like disjointWith. Here it infers that ADR_005 replaces ADR_001, which nobody wrote down. It never reports that something is missing.

[next]

SHACL works in a closed world. If a required field is missing, or an order gets a second refund, that is a violation. SHACL validates the shape of the data. For example, every Decision needs a rationale of at least 20 characters and an ISO date, and a Decision without them fails validation. SHACL runs in two modes: read-only gap audits, which surface missing owners or metadata without slowing anyone down, and write-time blocking gates, which refuse incomplete records before commit. OWL tells you what follows from the data, and SHACL tells you whether the data is complete enough to use.

[next]

These four are what Netflix built its map on, the one from the home screen story. This is the detail I would copy first. Their post says they refused a generic Service type. Across twelve namespaces and a software catalog of roughly 49,000 entries, every app has one concrete type. Once a generic type exists, people file new things under it because it is the easy choice, and then the type tells you nothing.

So far this is all nouns and facts. A read-only graph helps an agent understand; binding logic and actions is what makes it safe to act.
