Start with what most teams do today. One large model answers every question the harness has. Which package does this task belong to? Is this action risky? Is the refund within the limit? Each check adds another LLM round-trip. In LangChain's talk on agent harnesses, the speaker noted she had turned off auto mode in her personal coding agent because its LLM risk checks were too slow.

[next]

The fast, fuzzy harness calls can move to a non-generative decision model. It takes unstructured state plus typed questions and returns calibrated probabilities in one pass instead of generating tokens. TypeSafe AI launched Jev and OpenAI announced its Decisions API in September 2026; TypeSafe reports up to about 200 times faster and 400 times cheaper than an LLM call, which is the vendor's top-of-range figure. In LangChain's A/B tests, LLM-routed threads actually ran slower than unrouted ones until they swapped in Jev, cutting median cost by 64% with no drop in merged-PR rate. Browserbase saw median act() latency fall from 1.97 seconds to 0.46 seconds by falling back to an LLM only below a confidence threshold.

The refund limit is a different kind of question. It has one right answer, and a guess is not acceptable. A decision model guarantees the shape of its output, not its truth, and it can't do arithmetic or graph logic. So hard limits go to symbolic rules, meaning ontologies, types and lints. They are deterministic and take milliseconds.

That leaves the large model with the work only it can do, which is open-ended synthesis such as writing the change. LangChain quotes Jaya Gupta's phrase for this: cheap by default, frontier on exception. Symbolic checks own the hard invariants, decision models own the fast fuzzy calls, and the frontier model handles the rest.
